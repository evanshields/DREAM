## Critical Issues (Must Fix Immediately)

### Issue #1: Missing `tabular-nums` on ALL Financial Metrics
**Severity:** Critical  
**Category:** Typography / CRE Usability  
**Location:** Multiple files

**Description:**
The most critical CRE usability issue: **No financial metrics use `tabular-nums` class**, which is absolutely essential for numeric alignment in tables and comparison views. The design language explicitly states: "Always use `tabular-nums` for financial metrics."

**Affected Components:**
- `AnalysisView.tsx` lines 23, 89, 94 - Metric values without `tabular-nums`
- `MetricCard.tsx` line 50 - Numeric display missing `tabular-nums`
- `PipelineBoard.tsx` line 37 - Price display without `tabular-nums`
- All table cells with numeric data

**Design Language Reference:**
> "Always use `tabular-nums` class" (line 130)
> "Numeric Columns: Right-aligned with `tabular-nums`" (line 252)

**Impact:**
- Poor numeric alignment in tables
- Difficult to scan financial data
- Unprofessional appearance for financial application
- Violates core CRE usability principle #1 (numeric legibility)

**Proposed Fix:**

File: `src/components/MetricCard.tsx`
```typescript
// BEFORE (line 50):
<p className={`text-3xl font-heading font-semibold mt-2 ${statusColors[status]}`}>
  {value}
</p>

// AFTER:
<p className={`text-3xl font-heading font-semibold mt-2 tabular-nums ${statusColors[status]}`}>
  {value}
</p>
```

File: `src/pages/AnalysisView.tsx`
```typescript
// BEFORE (line 23):
<span className="text-3xl font-bold text-secondary font-heading">{value}</span>

// AFTER:
<span className="text-3xl font-bold text-secondary font-heading tabular-nums">{value}</span>
```

Apply this fix to ALL components displaying numeric data:
- Metric cards (lines 23, 89, 94 in AnalysisView.tsx)
- Table cells with financial data (lines 152-166)
- Price displays (PipelineBoard.tsx line 37)
- All other numeric values

### Issue #3: Hardcoded Colors Instead of Design Tokens
**Severity:** Critical  
**Category:** Design System / Maintainability  
**Location:** Multiple files

**Description:**
Throughout the codebase, components use hardcoded hex colors (`#005253`, `#2B52EF`, etc.) instead of design tokens. This violates the design system and makes it impossible to maintain consistent theming.

**Examples of Violations:**
- `Layout.tsx` line 32: `bg-[#005253] dark:bg-[#2B52EF]`
- `Layout.tsx` line 39: `text-[#005253] dark:text-[#2B52EF]`
- `Layout.tsx` line 91: `text-[#005253] dark:text-[#2B52EF]`
- `Layout.tsx` line 327: `bg-[#005253]` (avatar)
- `AnalysisView.tsx` line 20: `border-t-[#005253]`
- `AnalysisView.tsx` line 41: `bg-[#005253]`
- `AnalysisView.tsx` line 82: `from-[#005253]`
- `AnalysisView.tsx` line 310: `text-[#005253]`
- `UIComponents.tsx` line 23: `bg-[#005253]`
- `UIComponents.tsx` line 88: `focus:ring-[#005253]`

**Design Language Reference:**
Design language specifies using named tokens, not raw hex values.

**Impact:**
- Cannot enforce design language compliance
- Difficult to maintain color consistency
- Dark mode transitions don't work properly
- Cannot update brand colors globally
- Theme switching is unreliable

**Proposed Fix:**

All hardcoded colors should use Tailwind classes with design tokens:

```typescript
// BEFORE:
<header className="bg-[#005253] dark:bg-[#2B52EF]">

// AFTER:
<header className="bg-accent dark:bg-yinmn-blue">
```

```typescript
// BEFORE:
<div className="border-t-[#005253]">

// AFTER:
<div className="border-t-accent">
```

```typescript
// BEFORE:
<input className="focus:ring-[#005253]">

// AFTER:
<input className="focus:ring-accent">
```

**Note:** After fixing CSS variables (Issue #2), all hardcoded colors must be replaced with Tailwind utility classes using the design token names.
