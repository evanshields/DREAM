## What is implemented

- Publication jobs use the existing signed-in identity and explicit deal association. HTTP requests cannot supply an actor, source path, projection or renderer configuration.
- The server requires a current passing calculation, complete input evidence and matching comps and go reviews. Requests bind the exact revision, result and review event identities.
- Request keys bind the actor and payload. Repeating a request returns its original job, including after a later edit. The store preserves history after restart without automatically resubmitting interrupted work.
- The private worker verifies the workbook, builds all four deliverables and returns its final receipt. The app independently verifies files, the archive, projection and native workbook proof before promoting a current package.
- Edits or withdrawn approvals during rendering leave completed files historical. Cancellation before completion prevents promotion, including a cancellation that races with the final database update.
- Uncertain native cleanup creates a shared quarantine record. New calculations and publishing are blocked until cleanup is verified. An observation timeout never authorizes killing an Office owner.
- The screen shows readiness, saved progress, cancellation, document history and current downloads. Download requests use fixed document and format choices. They never accept a caller-supplied path. Every download rechecks current source identities, reviews and package bytes.

The archive is an internal underwriting record containing the original workbook and private audit evidence. Capital documents use the alias. Generating or downloading a package does not authorize external distribution.

## Local server registration

An optional `publication` entry within an existing Mono deal registration contains either `source_plan`, `artifact_root`, `source_plan_sha256` and `renderer_sha256`, or `projection`, `artifact_root`, `projection_sha256` and `renderer_sha256`. Paths and pins belong to the server configuration. HTTP callers cannot select them.

A source-plan request freezes static evidence and current native result and review identities. A separate native process extracts fresh workbook evidence under the shared Excel mutex. The compiler fills the route's declared slots and pins the resulting projection separately from the source-plan request hash. Final assembly reopens the workbook in a fresh isolated Excel instance. Before promotion, the app independently verifies the actual package and recompiles the frozen plan against retained native evidence. A fixed candidate must already match the current result and review events. Changed source bytes, policy, code or approvals invalidate either path.
